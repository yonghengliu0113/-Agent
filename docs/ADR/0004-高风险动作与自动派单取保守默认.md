# 0004 高风险动作与自动派单取保守默认

- 状态：已采纳
- 日期：2026-10

## 背景

LLM 会被"我要退款""你们赔我"这类表达带着走，直接给出承诺或触发写操作。产品上又确实需要"能办事"，否则只是个问答机器人。

真正的风险不是"答错一句话"，而是**不可逆的业务动作**被自动执行：退款、赔付、关闭投诉、删除数据、覆盖人工派单。

## 决策

1. **高风险动作不由 AI 执行**。退款、赔付、删除、关闭投诉、真实退货申请，一律进入人工审核或建单流程，AI 只出草稿与建议。
2. **规则兜底优先于模型判断**。即使 LLM 判定可以自动回复，`agents/customer_service_agent.py` 的 `_apply_business_guardrails` 仍会按规则把售后争议、投诉、赔付、维权、低置信度改写成 `need_human=True` / `need_ticket=True`。
3. **自动派单默认关闭**。未配置 `AGENT_AUTO_ASSIGN_TICKET` 时全部工单保持 `PENDING_ASSIGN`；开启后也只允许低风险、规则明确、非真实业务动作的工单。
4. **人工选择不可被覆盖**。`assignedBy = MANUAL` 的工单，后续智能派单不得改写处理人。
5. **自动派单只做推荐与落库**，不让 LLM 直接决定"派给谁"。
6. **可见性隔离**：客户侧只能看到 `customer_message`、`service_status`、工单号与状态；`risk_reasons`、`decision_type`、AI 分析、工具原始结果、Prompt 一律不下发。

## 后果

正面：

- 最坏情况是"答得不好"而不是"赔了钱"，风险可控；
- 兜底在规则层，提示词被注入或模型降智时仍然生效；
- 派单策略保守意味着不会因为模型误判把投诉单塞给不合适的坐席。

代价：

- **自动化率偏低**：很多本可自动处理的场景会转人工，人力成本上升。这是刻意的取舍。
- 规则与模型双轨意味着同一判断有两处实现，改规则时必须同步检查 prompt 与 guardrails，否则会出现"模型说转、规则说不用转"的漂移。
- 客户看不到风险原因，沟通中可能需要坐席额外解释，体验上略打折。
- 保守默认让"自动派单"这个能力长期处于关闭状态，缺少真实流量验证，开启前需要专项压测。

## 复审条件

出现以下情况应重新评估本决策：投诉误派造成实际业务损失、转人工率长期高于阈值、或引入独立的策略引擎可以把规则集中管理。
